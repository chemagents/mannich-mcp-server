# Подключение к CoScientist

Этот документ предназначен команде развёртывания. Общий адрес сервиса ещё не выделен; ниже описано, как развернуть и проверить собственный экземпляр.

## Контракт интеграции

| Параметр | Значение |
|---|---|
| Транспорт | MCP Streamable HTTP |
| MCP route | `/mcp` |
| Файлы результатов | `/files/{sha256}.{extension}`, тот же сервис |
| Имя в реестре | `mannich-2026` |
| Научная область | `mannich_2026`; DOI `10.1038/s41597-026-08287-9` |
| Инструменты | 10; точные имена и схемы в [api/tools.json](../api/tools.json) |
| Входы | Закреплённый набор статьи; числовые параметры и режимы согласно схеме |
| Ключ языковой модели | Серверу не нужен; LLM настраивается в CoScientist |
| Версия backend | `a2d980330bd90275722d401c6c9ca246a536dd01` |

Планирование, состояние исследования, сбор артефактов и итоговый текст принадлежат CoScientist. MCP возвращает химические расчёты и их происхождение. API не требует локальных изменений промптов CoScientist для обнаружения инструментов, но успешное подключение не является доказательством качества всех сквозных ответов.

## Установка на вычислительном хосте

Нужны Git, Python3.12 и uv. Версии зависимостей закреплены в `uv.lock`.

```bash
git clone https://github.com/chemagents/mannich-mcp-server.git
cd mannich-mcp-server
uv sync --frozen --python 3.12
```

Оператор задаёт `MCP_BASE_URL` — реальный базовый адрес этого экземпляра без `/mcp`, доступный из окружения backend CoScientist. Для адреса через внешний шлюз используйте HTTPS. Если шлюз маршрутизирует по префиксу, он должен снимать этот префикс перед передачей в приложение и одинаково обслуживать `/mcp` и `/files/…`.

```bash
uv run python scripts/configure_endpoint.py --base-url "$MCP_BASE_URL"
set -a
. deployment/server.env
set +a
export CHEM_REPRO_ARTIFACTS_DIR="$PWD/outputs"
uv run mannich-mcp-server
```

Генератор создаёт `deployment/registration.json` и `deployment/server.env`; существующие файлы не перезаписываются. Это подготовка конфигурации, а не создание DNS, сертификата или развёртывание. Локальные и примерные адреса отклоняются по умолчанию. Для намеренного внутреннего HTTP-соединения есть `--allow-http`.

## Контейнер

```bash
docker build -t mannich-mcp-local .
docker run --rm --name mannich-mcp \
  --env-file deployment/server.env \
  -v "$PWD/outputs:/outputs" \
  -p 127.0.0.1:7343:7343 \
  mannich-mcp-local
```

Здесь loopback — **внутренний порт на хосте шлюза**, не адрес регистрации CoScientist. Если шлюз работает в другом контейнере, используйте адрес сервиса в общей контейнерной сети. Контейнерный образ собирается командой выше; готовый образ в публичном registry этим репозиторием не объявлен.

Основные статистики и классификация работают в базовом окружении. t-SNE требует дополнительного времени CPU. `mannich_regenerate_catalyst_structures` запускает генерацию конформеров; по умолчанию охватывает все 468 катализаторов. Для первичной проверки подключения этот вызов не нужен.

## Регистрация в CoScientist

Формат проверен по `scripts/rag_tools/cli.py` в CoScientist_dev revision `900aeae29d77416a798bdf706bc1c6df8d8e1911`. Команду нужно выполнять **из настроенного checkout CoScientist**, где уже работают его реестр и зависимости поиска инструментов:

```bash
uv run python -m scripts.rag_tools.cli load /absolute/path/to/deployment/registration.json
uv run python -m scripts.rag_tools.cli list
```

Проверенная команда `load` читает `name`, `url`, `description` и необязательный `token`. Поле `timeout` в таком JSON она не применяет. В проверенном динамическом клиенте CoScientist таймауты задаются переменными `MCP__REQUEST_TIMEOUT` и `MCP__SSE_READ_TIMEOUT`; значения по умолчанию 60 с и 7200 с. Они настраиваются **в процессе CoScientist**, вместе с таймаутом шлюза. Долгие расчёты требуют соответствующего профиля выполнения; один увеличенный HTTP-таймаут не гарантирует завершения отчёта агента.

Встроенная авторизация в данном адаптере не настроена. Если развёртывание использует защищённый шлюз, оператор обеспечивает доступ как к MCP, так и к файлам результатов; конфигурацию с токеном хранит вне Git. Проверенная команда `load` может вывести ошибку отдельного сервера и продолжить работу, поэтому одного exit code недостаточно: проверьте список серверов и обнаруженные инструменты.

## Проверка с хоста CoScientist

В окружении адаптера, но на машине/в сети клиента:

```bash
uv run python scripts/check_endpoint.py --url "$MCP_BASE_URL/mcp"
```

Проверяется полный список инструментов, один обзор исходных данных и скачивание каждого возвращённого файла с проверкой размера и SHA256. Для шлюза с авторизацией можно передать `--headers-file /secure/path/request.headers.json`: JSON-объект HTTP-заголовков применяется к MCP и скачиванию файлов.

Не подменяйте эту проверку открытием `/mcp` в браузере: обычный GET может не соответствовать протоколу MCP. Если инструменты доступны, но файлы недоступны, сначала проверьте `CHEM_REPRO_PUBLIC_BASE_URL`, маршрутизацию `/files/…` и заголовки доступа.

После успешной проверки оператор регистрирует фактический адрес в CoScientist и объявляет его пользователям своей установки. Если адрес публикуется в этом репозитории, поле `deployment.shared_endpoint` в `server.json` меняется только после проверки работающего сервиса.

## Результат инструмента

- `answer.metrics` и `answer.tables`: значения, единицы, определения популяций.
- `evidence_kind`: `computed` — вычислено; `source_record` — исходная запись; `paper_reported` — опубликованное значение.
- `metadata`: DOI, протокол, параметры, версии ПО и хеши источников.
- `answer.limitations`: ограничения и расхождения, которые нужно сохранить в отчёте.
- `artifacts`: `download_url`, `size_bytes`, `sha256`. Большая таблица в JSON может быть только превью; используйте `is_preview`, `total_rows` и ссылку на полный CSV.

`success` означает успешное выполнение расчёта, а не автоматическое совпадение со статьёй. `partial` означает частичный результат; `unsupported` — отсутствие поддерживаемого способа выполнить запрос в заданных условиях. Проверяйте также ограничения и таблицы сравнения.

Научные вызовы сериализуются внутри одного процесса; обнаружение инструментов и скачивание файлов остаются доступными. Отмена HTTP-запроса не гарантирует мгновенной остановки уже начавшегося вычисления. Для общего сервиса оператор планирует очереди и постоянное хранение `/outputs`.

## Локальная разработка

```bash
uv run mannich-mcp-server
uv run python scripts/smoke_server.py --study mannich
```

Только в этом сценарии используется `http://127.0.0.1:7343/mcp`. [Локальный JSON](../examples/registration.local.json) подходит клиенту на том же хосте; в другом контейнере `127.0.0.1` обозначает уже другой компьютерный процесс/контейнер.

Поддерживается и `--transport stdio`, если клиент самостоятельно запускает процесс. Для скачивания артефактов требуется доступный HTTP-путь; для общего развёртывания и стандартного сценария CoScientist используйте HTTP.
